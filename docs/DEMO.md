# PaceShelf walkthrough

[Watch or download the walkthrough (MP4)](https://github.com/jayelbotvibe-web/paceshelf/releases/download/v0.1.0-preview/PaceShelf-Walkthrough.mp4).

This short, intentionally silent recording shows the actual **0.1.0 Ubuntu
browser player**, using an isolated, fictional library. On-screen explanations
describe each action. It is a feature demonstration, not physical Android/USB
handoff or battery-test evidence.

## Follow the same steps

1. **Browse your library.** The example contains Photography Foundations, Sketching
   Essentials and Everyday Astronomy. Collections show completion, favorites and
   a Continue learning shortcut.
2. **Resume a lesson.** Select Continue learning to reopen the current lesson at
   the saved playback position.
3. **Adjust playback speed.** Open the speed control and select 1.5×. Your choice
   is remembered for later lessons.
4. **Bookmark a useful moment.** Select Bookmark, then expand Bookmarks to see the
   lesson and timestamp. Select a bookmark to return to that point.
5. **Track completion.** Mark a lesson complete and undo the change. Completion
   is a separate choice from where you paused the video.
6. **Pause and return.** Go back to the library to find your updated progress.
7. **Choose a storage mode.** On this device keeps history local. Portable library
   writes checked metadata beside the videos, allowing the same drive to carry
   progress to another PaceShelf installation.

Before moving a real drive, pause, confirm a verified portable save, use Safely
remove and complete the operating system's unmount step. The recording switches
settings on a local demonstration folder; it does not show physical drive removal.
There is no automatic cloud synchronization.

## Images and privacy

The README's local-player images are derived from this same demonstration. The
0.2.0 YouTube-import image uses a separate fictional, links-only preview. Phone and tablet
images are responsive browser captures of the shared interface, not photographs
or claims of completed hardware testing. The sample clips are original geometric
animations generated by `tools/create-demo.py`; no third-party course material is used.

Only the app viewport is captured. Personal files, desktop chrome, user accounts,
real library metadata, paths and notifications are excluded. Still images are
re-encoded without metadata and pinned by SHA-256 in the publication manifest.
The recording and descriptive WebVTT track are release assets; raw capture frames,
sample clips and temporary metadata remain ignored under `dist`.

The video has burned-in explanations. Its optional `.vtt` download repeats those
descriptions for reuse; it is not a speech transcript. Leave an external caption
track off when viewing the burned-in version to avoid duplicate text.

## Reproduce the demonstration

Use Python 3 with Pillow, FFmpeg, Fontconfig with DejaVu Sans, Node 22 or newer,
Go, and a Chromium-based browser. No paid media service or account is required.
The production scripts are provided so the examples can be regenerated and reviewed.

From a fresh checkout, generate the isolated sample library and build the desktop player:

```sh
python3 tools/create-demo.py --output dist/demo-work
cd desktop
go build -trimpath -o ../dist/paceshelf .
cd ..
./dist/paceshelf -root "$PWD/dist/demo-work/Demo Library" \
  -data "$PWD/dist/demo-work/device" -addr 127.0.0.1:8391
```

In another terminal, start an isolated Chromium profile. Adjust the browser
executable name for your installation:

```sh
chromium --headless --hide-scrollbars --no-first-run \
  --autoplay-policy=no-user-gesture-required \
  --remote-debugging-port=9231 \
  --user-data-dir="$PWD/dist/demo-work/browser" \
  --window-size=1280,800 http://127.0.0.1:8391
```

Record the app, then render the MP4, explanatory text track and still images:

```sh
node tools/record-demo.mjs dist/demo-work
python3 tools/render-demo.py --work dist/demo-work \
  --assets dist/demo-work/documentation
```

Recording controls run against the actual app. A guard checks the selected root
and the three synthetic collection names before capture. Keep the local debugging
port restricted to loopback. Stop the demonstration browser and server afterward.

The renderer preserves the capture timing and adds one readable explanation band
below the app viewport. Final video is H.264, 1280 × 900 at 20 fps, with no audio.
`timeline.json` retains capture timing and text cues; `render-report.json` records
runtime, provenance and hashes. Use a fresh output directory to repeat the recording;
do not reuse a library containing old demonstration progress.

Before publication, inspect the entire exported sequence, images and metadata.
Review and copy only the three approved WebP images to `docs/assets`, then update
their exact manifest hashes. Never publish raw fixtures, browser profiles, logs or
unreviewed captures. See [publishing safeguards](../PUBLISHING.md).
